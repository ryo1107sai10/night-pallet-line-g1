# Night PRO LINE

要件定義書 第1.0版に基づくLINE接続・シナリオ・顧客台帳・来店予約の実装です。管理画面とAPI、PostgreSQLのマイグレーション、LINE配信ワーカー、ローカル試験を含みます。

## ローカルで起動

Node.js 24以上とnpmが必要です。ローカル起動はnpmに組み込みPostgreSQLのバイナリがある環境（例としてmacOS arm64）に対応しています。展開したフォルダで以下を実行します。

```sh
npm ci
npm run build
npm run local
```

1. ブラウザで [管理画面](http://127.0.0.1:3000/) を開きます。
2. 初回起動で作成される `.local/first-invite.json` を開きます。認証アプリに `setup_key` を時刻ベースで登録し、管理画面の「招待を受け取った方」に `invite_code`、新しいパスワード、現在の6桁コードを入力します。
3. 法人ID `demo`、メール `admin@example.test`、設定したパスワードと**次の6桁コード**でログインします。
4. 「新しい店舗を登録」から店舗を作り、「LINE接続」から公式アカウントの設定を登録できます。

初回招待は24時間有効です。有効化前に期限切れになった場合は、起動中のアプリを停止し `npm run local -- --renew-invite` で再発行します。ポートが使用中の場合は、`LOCAL_WEB_PORT` と `LOCAL_DB_PORT` を変更できます。ローカルデータは `.local/` に保存されます。初回招待を利用した後は、`.local/first-invite.json` を削除できます。

ローカル起動では実LINEへの検証・送信を無効にしています。ローカル結合試験ではLINE API応答を差し替え、HTTP、実PostgreSQL、ワーカーを通して確認します。

```sh
npm test
```

## 実LINEでG1を検収

検証担当者が管理できるテスト用LINE公式アカウントと公開HTTPS環境を用意します。実際に利用する店舗、アカウント所有権とプロバイダー、LINEの利用条件は D01〜D04・D14 の記録に従って確定します。

1. PostgreSQLに移行用ロールと実行用ロールを作ります。移行用は対象DBでスキーマ作成・所有ができる構成とし、実行用は `LOGIN NOSUPERUSER NOBYPASSRLS` とし、所有者ロールのメンバーにしません。初回設定で `.env.example` を参照して `PUBLIC_ORIGIN`、`MASTER_KEY`、`DATABASE_URL`、`MIGRATION_DATABASE_URL` を設定します。
2. ビルド後に `npm run setup -- pilot "検証用法人" admin@example.test` を実行し、表示された招待を管理者に渡します。マイグレーションのみ実行する場合は `npm run setup` です。サーバー・ワーカーには実行用のDB接続情報と暗号鍵を設定し、移行用の接続情報は初回設定時だけ使用します。
3. `npm start` と `npm run worker` を起動します。既定ではアプリは `127.0.0.1:3000` で待ち受けます。HTTPSの入口から転送し、公開URLは `PUBLIC_ORIGIN` と一致させます。プロキシ配下のIP制限は接続元単位で機能するよう入口にも設定してください。
4. 管理画面で店舗と検証用OAを登録します。プロバイダー、OA所有、各チャネルID、ボットユーザーIDをLINE Developersで照合し、認証情報は管理画面の専用欄に入力します。
5. 接続画面に表示されたURLをLINE Developersに設定します。Webhookを有効にして再送を設定し、既存の応答設定・ツールとの重複を点検します。LINEログインチャネルを公開し、LIFFのスコープに `openid` を追加します。LIFFのエンドポイントは表示されたURLをそのまま登録します。
6. 管理画面で公式管理画面の確認結果を保存し、「トークンとボットの照合」「Webhookの疎通」の順に確認します。公開中のOAのWebhookを変更する場合、既存ツールに影響するため、ここでは検証用OAを使用します。
7. 開発者権限のないテスト利用者へLIFF URLと用途付きの招待コードを渡します。本人確認とテストメッセージの受信許可を行ってもらい、同じLINEアカウントから検証用OAへメッセージを送ってもらいます。「テストの進捗を更新」で受信を確認し、テスト送信を1通だけキューに登録します。
8. 管理画面の「LINE受付済」と実機の受信を照合し、公式管理画面の確認欄に実機確認を記録します。「接続済」は全項目の確認後に表示されます。試験日、使用したOA、端末、操作担当、結果を記録します。

この構成はG1の接続検証用です。本番運用に向けて、D10〜D12の保存・鍵管理・監視・復元体制、認証回復と運用者委任、利用規模に応じたワーカー分割と負荷試験を確定します。

## シナリオスタジオ

管理画面でログイン後、「シナリオスタジオを開く」から作業します。スタジオのURLは `/studio/` です。既存環境の更新では `npm run build` と `npm run setup` を行い、002マイグレーションを適用してからアプリとワーカーを再起動します。

- 店舗・公式アカウント・顧客用途/採用用途を選び、開始イベント、待機、メッセージ、条件分岐、タグ、担当タスク、終了を編集できます。
- LINEプレビューでは差し込み後の本文を確認できます。配信前テストでは架空日時と条件を入力し、時刻調整、通数、分岐と除外理由を確認できます。日次・週次の既送件数はテスト条件として入力します。
- 下書きを保存してテストを記録すると、承認と公開版保存に進めます。公開版は更新・削除権限を付与しないテーブルに保存し、後続の下書きと分離します。
- 公開HTTPS環境で、同じ店舗・OA・用途の認証済みテスト利用者がいる場合は、シミュレーションで送信予定となった1ステップの本文を「接続テスト」表示付きでキューに登録できます。既存の緊急停止とテスト送信ワーカーを使います。
- 顧客向けの対応イベントと自動配信の条件は下の「顧客・予約と自動配信」を参照してください。受信箱と実LINE検収は未完了です。

[GitHub Pagesの操作デモ](https://ryo1107sai10.github.io/night-pallet-line-demo/) では架空データを使用し、変更は現在のブラウザにだけ保存されます。

公開資料から、シナリオ登録、待機、アクションでの分岐を参考にしました。 [プロラインのシナリオ作成](https://autosns.co.jp/manual/use/scenarios/create-scenario) · [ボタンによる分岐](https://autosns.co.jp/manual/use/scenarios/exec-measurement-tag-button) · [Appleのマテリアル指針](https://developer.apple.com/design/human-interface-guidelines/materials)

## 顧客・予約と自動配信

「顧客・予約」管理画面から、顧客台帳、来店受付枠、予約確定・変更・取消、配信結果を参照できます。顧客はLINE内画面で用途別の受信設定、来店申込、本人の予約変更・取消を操作できます。

公開版の自動実行は `AUTO_SEND_ENABLED`、店舗の有効化、契約と適格性、LINE接続確認、用途別の同意に従います。実機検収に必要な設定と、現在対象にしているイベントは [実LINE検収手順](LIVE-LINE.md) を参照してください。

## 採用面談の予約

採用用または兼用のLINE公式アカウントとLIFFを登録したら、管理メニューの「面談枠の管理」から日時、所要時間、対面／オンライン、確定者向けの案内を設定します。法人管理者・店舗責任者・採用担当が担当店舗の枠を公開できます。公開枠は1枠1名で、同じ店舗の公開・確定枠の時刻は重複できません。公開停止後も、すでに確定した予約は維持されます。

応募者はLINE内で本人確認し、週間カレンダーから日時を選び、確認画面で予約を確定します。日程変更と取消は「自分の面談」から行えます。インタビュー予約は来店予約と別の台帳で管理されます。この変更には `004_interviews.sql` が含まれます。既存環境では `npm run setup` を実行してからアプリを更新します。

[面談予約の公開デモ](https://ryo1107sai10.github.io/night-pallet-line-demo/interview/) では架空の枠で予約・変更・取消を試せます。実際のLINE公式アカウントでの検収は未実施です。

面談カレンダーは店舗の現地時刻で、既定は **18:00〜24:00、30分刻み**です。最終開始は30分面談の場合の23:30です。「面談枠の管理 → 受付時間の設定」で開始・終了を変更できます。受付時間は表示・予約可能な範囲で、予約を受け付けるには管理者が範囲内の枠を公開します。時間外になった枠は新規受付から外れ、確定済みの面談は「自分の面談」から確認・変更・取消できます。更新時は `npm run setup` で `005_interview_hours.sql` を適用してください。
